# Neural Column Generation for 2D Loading and LIFO-constrained Vehicle Routing

> **TL;DR:** The neural component predicts whether a classically generated route admits a valid loading. Exact checking and corrective cuts retain the host algorithm's correctness. This is a **specialist/constructive** learning-assisted exact solver, not an end-to-end neural route generator or a learned incumbent-route editor.

## Motivation

2L-CVRP combines vehicle routing with nonoverlapping rectangular loading, fixed item orientations and unloading without moving items for later customers. Exact pricing can quickly produce candidate routes whose packing feasibility is expensive to verify. The proposed NCG framework uses a learned screening oracle to avoid checking every route before insertion, while retaining exact checks where required. [Problem and motivation.](https://www.ijcai.org/proceedings/2024/0218.pdf#page=1)

## Contributions

- A column-generation pipeline defers selected packing checks using predicted feasibility.
- Attention processes items within each customer, and a GRU preserves the order of different customers required by LIFO.
- Within-customer permutations augment supervised feasibility examples.
- LP-relaxation timing experiments, classifier ablations and a separate branch-price-and-cut(BPC) result evaluate acceleration and exact solving. [Pipeline.](https://www.ijcai.org/proceedings/2024/0218.pdf#page=2)

## Methodology

### Classical optimization and exact correction

A set-partitioning master selects exactly the specified number of vehicle routes, serves every customer once and minimizes total travel cost. Pricing uses resource-constrained paths with weight/area bounds and the existing L-Trie machinery. Candidate columns are generated classically; the neural model does not choose their next customer or construct the packing coordinates.

Predicted-feasible columns can enter the restricted master without immediate packing verification. Predicted-infeasible columns are checked exactly so false negatives cannot silently remove a necessary feasible route. Columns in an optimal master basis are also checked; false-positive cuts exclude invalid ones. The stated exactness comes from this complete host correction/pricing process, **not** from a95%-accurate classifier. Standalone CG solves an LP relaxation; integer optimality requires the larger BPC framework. [Formulation and correction rules.](https://www.ijcai.org/proceedings/2024/0218.pdf#page=3)

### Packing-feasibility network

Item inputs are width/container-width and length/container-length. Two multi-head attention layers embed each customer's item set, with residual connections, feed-forward layers and normalization. A one-layer GRU receives the items across customers in route order; its final state passes through a feed-forward head and sigmoid. Hidden dimension is16, with four attention heads.

Items inside one customer can be permuted without changing physical feasibility. Tenfold permutation augmentation trains robustness to that arbitrary item order; it should not be described as an architectural proof that the GRU output is exactly permutation invariant. Weighted binary cross-entropy supplies the supervised objective. The recurrence ablation substitutes a position-encoded Transformer with mean pooling; the attention ablation substitutes a two-layer MLP. [Architecture.](https://www.ijcai.org/proceedings/2024/0218.pdf#page=5) [SupplementC.](https://github.com/xyfffff/NCG-for-2L-CVRP/blob/main/Supplementary%20Material.pdf)

## Experiments

### Data, training and execution budget

Packing examples are collected while solving generated2L-CVRP and2L-VRPTW instances with learning disabled. Random, clustered and mixed customer distributions provide data distinct from the standard test cases. The main benchmark uses packing classes2-4 with at most50customers; class1 reduces to one-dimensional loading, and class5 uses many small items and a specialized CG variant that is excluded.

The scientific supplement specifies Adam1e-4, batch512 and tenfold augmentation. Training hardware is an AMD EPYC7V13 64-core CPU and A100 GPU. Both compared optimization algorithms are C++ implementations running on the same Intel i5-10600KF at4.10GHz, using a serialized Torch model. The repository's replication command requests10,000epochs, seed1234; this command is distinguished from a fully disclosed training wall-time/epoch count in the paper. [Main protocol.](https://www.ijcai.org/proceedings/2024/0218.pdf#page=6)

### LP-relaxation acceleration and counterexamples

The stated percentage is **(T_SOTA-T_NCG)/T_NCG ×100**, using NCG time as the denominator. The median29.79% therefore corresponds to a1.2979ratio of baseline/new times, or about22.95% lower time relative to the baseline; it is not the usual29.79% baseline-relative time reduction. Packing-class medians are9.38%,44.97% and99.22% under that same definition.

The supplement lists57instances,19per class. Eight have negative improvements: NCG is slower on four class2, three class3 and one class4case. For example, `2l-cvrp1802-2010&9` takes272.98s versus209.80s. False-positive corrections often add CG iterations; other rows tie or reduce iteration counts. The medians summarize heterogeneous behavior rather than a universal speedup. [Figures3-4 and metric definition.](https://www.ijcai.org/proceedings/2024/0218.pdf#page=6) [Complete per-instance runtime/iteration tables.](https://github.com/xyfffff/NCG-for-2L-CVRP/blob/main/Supplementary%20Material.pdf)

### Classifier ablations and integer solving

The full model reports overall TPR94.08% and TNR96.80%; these are separate class-conditional metrics, not a documented universal95% classification accuracy. Class2 TPR is84.26%. The full architecture generally helps, but removing augmentation improves class3TNR from95.83% to96.69%, so every metric is not uniformly best.

For the formerly open instance `2l-cvrp-2304`, NCG-based BPC reports integer optimum1068 in49,544.6s. The baseline terminates from memory overload after69,948.96s with lower bound1066.78 and primal bound1069. This is one documented integer-solving improvement, with a different termination outcome; it is separate from the57LP-relaxation timing tests. [Tables1-2.](https://www.ijcai.org/proceedings/2024/0218.pdf#page=7)

## Limitations

The evaluated solver assumes identical vehicle loading areas, fixed rectangular orientations, no overlap and LIFO unloading. Training on some time-window instances does not demonstrate a generalist checkpoint across arbitrary native routing/packing problems. The network classifies ordered loading instances, while classical procedures still determine routes, packing feasibility and exact certificates.

Errors can increase correction iterations and make some cases slower. Results are limited to selected packing classes and the reported benchmark sizes, with no multiple-training-seed uncertainty or broad new application study. The public optimization component is distributed as a Windows executable rather than inspectable full source, limiting independent implementation checking. No training, executable or optimization run was performed in this review.
